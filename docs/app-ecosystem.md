# 应用生态策略

> 对应开发文档第六章「原生包格式 / 转包引擎 / 生态策略」。
> 格式与工具实现见 [../pkg/](../pkg) 与 [fos-package-format.md](fos-package-format.md)。

## 三层漏斗

```
┌─ 主流应用 ──────────────────────────────┐
│  官方适配优先：厂商按 .fos 规范原生重编   │  ← 最佳体验（全能力：超级环、
├─ 小厂/长尾应用 ─────────────────────────┤     健康使用、快照升级）
│  转包引擎：APK / deb / rpm → .fos        │  ← 立即可用（沙箱 +
├─ 独立开发者 ────────────────────────────┤     virt-compat 承接运行）
│  低门槛上架：python3 -m pkg build 即可   │  ← 生态的种子
└─────────────────────────────────────────┘
```

## 各层约定

| 层 | 上架要求 | 运行保障 |
| --- | --- | --- |
| 官方适配 | 签名 + `id` 归属认证 + 权限申报审核 | strict 沙箱、全系统能力 |
| 转包 | 自动通过格式校验；来源信息写入 `converter.info` 对用户透明 | strict 沙箱 + 翻译层；能力按转包子集 |
| 独立开发者 | 签名可选（社区侧装不强制验签，UI 提示未验证来源） | 同官方适配 |

## 沙箱模型（统一底线）

```
bwrap --ro-bind <安装目录>/data 只读根
      --bind ~/.fos/data/<id>  私有可写目录（配额见 manifest）
      --unshare-net（默认断网，申请网络 = 申报权限 network）
```

家长禁用（`health.can.launch`）在沙箱启动前最后一道拦截 ——
任何一层的应用都绕不过家庭规则。

## 与闭源分支的生态统一

`.fos` 清单 schema、转包引擎、沙箱约定为开轮版与闭源分支**共享**：
同一份包两端可装，生态不因分支而分裂。这正是「共享上层设计与
开发框架」（架构总览）在应用层的兑现。

## 治理（开轮版哲学）

- 商店排序公开算法、不因商业合作加权；
- 用户永远可以「侧装」：`familyos-fos install ./any.fos`；
- 下架只针对违法违规内容，争议处理流程公开在 Discussions。
